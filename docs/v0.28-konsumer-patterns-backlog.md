# v0.28 — Konsumer-Patterns Backlog

**Status:** Sammlung · 2026-05-06 · Sequenz + Naming korrigiert 2026-05-24
**Zweck:** Sammelpunkt für alles, was wegen Single-File-Anker (ADR-PC5) NICHT im Standard-Inspector gelandet ist, aber als **separate Konsumer-Variante** ab v0.28 Sinn ergibt.

> v0.28 wird Schaufenster für **"Inspector Advanced"-Click-Through-Pattern**: Standard-Inspector bleibt schlank/Single-File, Advanced-Variante bündelt Polyfills/3D/Composition für Power-User.

> **Naming-Entscheidung 2026-05-24:** Die zweite Distribution heißt **Inspector Advanced** — nicht "Inspector Pro". Begründung: B2B-passender, weniger Consumer-/SaaS-Konnotation. Pfad: `advanced/` (nicht `pro/`).

## 1. Architektur-Pattern (vorgeschlagen 2026-05-06)

### ADR-PC6-Skizze: Click-Through statt Bundle-Bloat

**Kontext:** Mehrfach im 2026-05-Sprint-Zyklus (v0.25.2 QR-Pivot, v0.25.5 Texture-Polyfill-Verzicht, v0.25.7 USDC-Material-Limitation) wurden Features verworfen, weil sie Single-File-Anker oder Privacy-First brechen. Lösung war jeweils "ehrlich rauslassen + Hint im UI" — aber das frustriert Power-User.

**Vorschlag:** v0.28 etabliert **Click-Through-Pattern**:

```
[Inspector Standard v0.27]            [Inspector Advanced v0.28+]
  ├─ Single-File HTML, schlank          ├─ Mit Polyfills (KTX2/TIFF/ASTC)
  ├─ Privacy-First                      ├─ Mit Three.js Desktop-3D
  ├─ Lokal-öffenbar                     ├─ Mit usd-wasm Composition
  ├─ "Mehr Features?  →"                ├─ Mit MCP-LLM-Findings-Erklärung
  └─ Click führt zu Advanced-URL        └─ Eigene URL, eigenes Hosting
```

**User wählt per Click**, was er für seinen Use-Case braucht. Beide Varianten Privacy-First (USDZ verlässt nie den Browser).

**Konsequenz:** Single-File-Anker bleibt für beide Varianten (Standard UND Advanced — jede ist für sich genommen Single-File). Advanced-Variante ist parallele zweite Distribution (z. B. unter `kopfkinok3.github.io/usdseal-inspector/advanced/` oder später `media.visales.de/inspector-advanced/`). Beim Click-Through muss User USDZ neu droppen (Cross-Domain-Privacy — kein Magic-Transfer möglich, das ist OK und ehrlich).

**Architektur-Entscheidung 2026-05-24 (v0.28.0-Spike):** Beide Varianten teilen einen gemeinsamen Source (`src/inspector.html`), aus dem ein Python-Build-Step zwei Distributions-Files erzeugt (`index.html` Standard + `advanced/index.html` Advanced). Eine gesamte Versionsnummerierung (`v0.28.0`), kein Drift. Details siehe `ROADMAP-v0.28.0.md`.

**Begriffsklärung 2026-05-24 (Phase-5.0-Befund Code-Chat):** "Advanced" bezeichnet die **Power-Distribution mit Feature-Tiefe**, nicht die "braucht mehr als 1 File"-Distribution. Treiber für das Two-File-Pattern ist der **Schlank-Anker des Standards** (~100-200 KB, Privacy-Reviewer-tauglich), nicht eine File-Anzahl-Notwendigkeit des Advanced:
- v0.28.0 Three.js: technisch single-file machbar via IIFE-Konsolidierung — aber Three.js (~700-800 KB) gehört nicht in den schlanken Standard
- v0.28.2 USDC-Parser: braucht definitiv multi-file (`.wasm`-Binary separat)
- v0.28.1 LLM / v0.28.3 Polyfills: File-Anzahl TBD pro Sprint

Standard bleibt strukturell schlank-anker-treu. Advanced bündelt was Standard ablehnt — File-Anzahl ist Implementierungs-Detail pro Sub-Sprint.

## 3. v0.28-Sub-Releases (Sequenz 2026-05-24 final)

```
v0.28.0  Pattern-Sprint + Inspector Advanced: Three.js Desktop-3D-Preview
         (Build-Step Variante Y in Python, gemeinsamer Source src/inspector.html,
          Standard mit Click-Through-Button, Advanced mit Three.js inline-eingebettet)

v0.28.1  Inspector Advanced: LLM-Findings-Erklärungen
         (MCP- oder API-Bridge, koppelbar mit v0.29 MCP-Server-Wrapper)

v0.28.2  Inspector Advanced: USDC-Material-Parser
         (usd-wasm-Embed, ggf. Hosting-Migration zu media.visales.de wegen COOP/COEP)

v0.28.3  Inspector Advanced: Texture-Polyfills
         (KTX2/TIFF/ASTC-Decode, GitHub Pages reicht)
```

**Verschoben:**
- **QR-Code-Modus-C (Upload + Server)** → frühestens bezahlte Pro-Variante (eigene Story, eigene Infrastruktur, eigenes Geschäftsmodell)
- **QR-Code-Modus-A/B (URL-Eingabe oder Katalog)** → optionaler Sub-Release nach v0.28.3 wenn Konferenz-Bedarf konkret

**Hosting-Strategie:**
- v0.28.0 / v0.28.1 / v0.28.3 → GitHub Pages reicht (kein COOP/COEP nötig)
- v0.28.2 → ggf. Migration auf media.visales.de (usd-wasm-SharedArrayBuffer-Frage)

Jeder Sub-Release nutzt den **gemeinsamen Build-Step** aus v0.28.0 — Standard und Advanced bleiben synchron durch ein Source-File mit Feature-Markern. Details siehe ADR-43 in CLAUDE-Inspector-private.md.

## 4. Strategischer Hebel

1. **Glaubwürdigkeit:** Standard-Inspector bleibt Privacy-First-/Single-File-Anker treu — "wir verkaufen kein Sandwich-Bundle".
2. **Power-User-Pfad existiert:** Wer mehr braucht, klickt sich zur Advanced-Variante. Kein "wir können das nicht" mehr.
3. **PR-Story:** "Inspector hat zwei Gesichter: schlank für 90 % der User, Advanced für die anderen 10 % — Du wählst."
4. **AOUSD-Talk:** Click-Through-Demo zeigt beide Welten. Der Standard-Inspector ist die Story, Advanced ist der Bonus-Slide.
5. **Monetarisierungs-Optionen offen:** Bezahlte Pro-Variante mit Server-Features (QR-Upload-Modus-C, Cloud-Bridges) bleibt als separate Distribution möglich, ohne den freien Stack zu kompromittieren.
