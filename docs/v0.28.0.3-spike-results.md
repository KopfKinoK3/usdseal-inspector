## 2. Identifizierte Failure-Muster

### Muster A — Tiny-Coordinator-USDC mit Kompositions-Arcs (BLOCK)

**RENZ_Showtime_Demo:** Root-USDC ist 3.8 KB — nicht die Geometrie, sondern ein Szenen-Graph-Koordinator. Enthält `variantSetNames` ("Hocker": Braun/Whiteboard), `variantSelection` und `references` auf `0/ShowTime_Hocker_TK.usd` (das ist die eigentliche Geometrie, USDC binary 73.6 KB).

Three.js USDLoader r184 lädt den Root-Layer und ignoriert die `references`-Komposition. Ergebnis: leere Szene, schwarzes Canvas. Kein Toast weil kein Exception ausgelöst wird.

**Vitra_ID_Demo_TK:** Identisches Muster — Root-USDC 13.6 KB, `references` auf 10 Sub-USDC-Files, `variantSelection` vorhanden. Vorhersage: BLOCK.

**Erkennungs-Signal:** Root-USD ist USDC binary (`PXR-` Magic) UND kleiner als ~100 KB UND binary-scan findet `'references'` oder `'variantSetNames'` im Klartext innerhalb der Binary. USD-Composition-Arc-Keywords sind in USDC-Crate als ASCII-Strings gespeichert und zuverlässig auffindbar.

### Muster B — Multi-USDC-Komposition mit Sub-USDZ (BLOCK)

**Frankfurt_Varianten_TK:** 79 Dateien, 21 USDC-Module, 2 eingebettete Sub-USDZ (`0/ID_Leg_5_Star.usdz` 10 MB, `0/TischMicro.usdz` 209 KB). Root-USDC (484 KB) ist Szenen-Koordinator der gesamten Konferenzraum-Szene. Three.js USDLoader kann weder die Kompositions-Arcs auflösen noch in sub-USDZ recursen. Ergebnis: silent parse rejection, `group.children.length === 0`.

**Erkennungs-Signal A:** Anzahl `.usdc`-Dateien im ZIP >= 5.  
**Erkennungs-Signal B:** Beliebige `.usdz`-Datei im ZIP (Sub-USDZ-Embedding).

### Muster C — Große selbstständige USDC, Material dunkel (CAUTION)

**DIEGOsat_TK_280426:** Root-USDC 21.5 MB — die gesamte Geometrie ist self-contained. Keine Kompositions-Arcs. Geometrie rendert korrekt. Materialien aber dunkel: Das Asset nutzt ORM-Textur (`material0_occlusion_roughness_metallic.png`) — ein kombinierter PBR-Channel, den Three.js USDLoader nicht vollständig auflöst. Kein Crash, aber visuell unvollständig.

**Erkennungs-Signal:** Datei-Größe > 20 MB mit selbstständigem Root-USDC. Kein direktes ORM-Detection-Signal nötig — Größe ist ausreichend konservativer Proxy.

### Muster D — Einfache selbstständige USDC (PASS)

**SalmonPasta:** Root-USDC 4.6 MB, 4 JPG-Texturen in `0/`-Subdirectory, keine Kompositions-Arcs, keine Variants. Three.js rendert vollständig. File-Größe < 10 MB.

**Erkennungs-Signal:** Keine der BLOCK/CAUTION-Trigger erfüllt.

## 3. Heuristik-Entwurf (Go-Pfad)

```javascript
function classifyAssetForPlayer(memberHashes, rootLayerData, fileSizeBytes, channelInfo) {
  const members = memberHashes || [];

  // BLOCK A: Eingebettete Sub-USDZ → Three.js kann nicht recursen
  if (members.some(m => /\.usdz$/i.test(m.name))) {
    return { level: 'BLOCK', reason: 'block_sub_usdz' };
  }

  // BLOCK B: Viele USDC-Module → Multi-Kompositions-Szene
  const usdcCount = members.filter(m => /\.usdc$/i.test(m.name)).length;
  if (usdcCount >= 5) {
    return { level: 'BLOCK', reason: 'block_multi_usdc' };
  }

  // BLOCK C: Tiny-Coordinator-USDC + Kompositions-Arcs
  if (rootLayerData) {
    const rootIsUsdc = rootLayerData[0] === 0x50 && rootLayerData[1] === 0x58 &&
                       rootLayerData[2] === 0x52 && rootLayerData[3] === 0x2D; // PXR-
    if (rootIsUsdc && rootLayerData.length < 100 * 1024) {
      const text = new TextDecoder('latin1').decode(rootLayerData);
      if (text.includes('references') || text.includes('variantSetNames')) {
        return { level: 'BLOCK', reason: 'block_variants_refs' };
      }
    }
  }

  // CAUTION: Große Datei → Performance-Risiko + material-darkness möglich
  if (fileSizeBytes > 20 * 1024 * 1024) {
    return { level: 'CAUTION', reason: 'caution_large_file' };
  }

  // CAUTION: 2–4 USDC-Module → partielle externe Komponenten
  if (usdcCount >= 2) {
    return { level: 'CAUTION', reason: 'caution_multi_usdc_minor' };
  }

  return { level: 'PASS', reason: null };
}
```

**Konservativität-Prinzip:** Lieber zu oft CAUTION als falscher PASS. User-Vertrauen > Optimismus.

**Technische Voraussetzung:** `rootLayerData` (Uint8Array) und `memberHashes` sind im `processFile()`-Scope zum Zeitpunkt des `setPlayerReady()`-Calls verfügbar. Kein Code-Umbau nötig, nur Weitergabe als neue Parameter.

## 5. Three.js Issue-Tracker — Recherche-Befunde

Recherche 2026-05-25 via Web-Suche:

- **Issue #28693** ("USDZLoader doesn't support all .usdz files"): Bestätigt Hierarchie-Einschränkungen — bestimmte Szenen-Hierarchien laden nicht. Konsistent mit Muster A (Koordinator + References).
- **Issue #24574** ("USDZ assets containing USDC files throw warning"): USDC-Handling hat bekannte Limits — Warnungen bei USDC-Parsing. Konsistent mit Muster C (Material-Dunkelheit bei komplexen USDC).
- **Issue #29169** ("Feature request: TinyUSDZ loader"): WebAssembly-basierter Ansatz als Alternative zu r184-Loader diskutiert. Kein Release-Datum (Stand 2026-05).
- **Cinevva Tech Report** (app.cinevva.com): Bestätigt, dass Three.js USDLoader USDC binary unterstützt, aber "limited USDC support and minimal composition". Explizit: Variants werden nicht aufgelöst.

Fazit Recherche: Alle vier identifizierten Failure-Muster sind durch bekannte Three.js-Grenzen erklärbar. Keine neuen BLOCK-Trigger gefunden, die über die Matrix hinausgehen würden.

## 7. Offene Punkte / Grenzen der Heuristik

- **AR_Wohnzimmer** und **Vitra_ID_Demo_TK** wurden nicht im Browser getestet — Vorhersagen basieren auf Struktur-Analyse. Browser-Verifikation folgt in Phase 5.7.
- **Threshold 100 KB** für "Tiny Coordinator USDC" ist empirisch aus RENZ (3.8 KB) und Vitra (13.6 KB) abgeleitet. Frankfurt's Koordinator (484 KB) wird von Muster B (>= 5 USDC) abgedeckt — der Threshold muss ihn nicht erfassen.
- **Threshold 20 MB** für CAUTION ist konservativ (DIEGOsat 26 MB liegt drüber, AR_Wohnzimmer 14.9 MB liegt drunter). Ein False-Positive auf CAUTION ist akzeptierbar — lieber einmal zu viel warnen.
- **Variants in USDA-Text:** Variants könnten auch in USDA-Files stehen. Im heutigen Pool nicht aufgetreten — USDA-Assets sind alle Test-Fixtures. Falls ein echter USDA-Variants-Fall auftritt, kann Muster A (binary-scan) um USDA-text-scan erweitert werden.
